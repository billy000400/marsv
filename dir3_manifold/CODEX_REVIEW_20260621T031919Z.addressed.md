## Remaining Misunderstandings / Overclaims

1. **"Stable across token position" is too strong.**

   TwoNN is stable across position buckets, but MLE ranges from about 8.65 to 13.26.
   That is not fatal, but the writeup should say "roughly similar, with
   estimator-dependent variation," not simply "stable."

2. **"Not a pooling artifact" is too strong.**

   The position check controls coarse absolute position only. It does not control
   token identity, document/topic clustering, duplicate text, or local sequence
   correlations. The result is evidence against one pooling artifact, not against
   pooling artifacts in general.

3. **The synthetic validation does not fully validate the real-data estimate.**

   The validation uses isotropic Gaussian subspaces linearly embedded into 768-d.
   That is useful, but it is much easier than curved, anisotropic, clustered
   residual-stream data. The writeup's inference that layer-6 estimates are "in the
   estimators' accurate regime" is too confident.

4. **The parameter-count argument remains hand-wavy.**

   Reporting parameter counts is good, but saying the confound "runs the wrong way"
   does not remove it. More parameters at high k still affect reconstruction curves.
   A parameter-matched AE sweep is needed if the AE result is going to matter.

5. **The folder is still direction #3, not direction #9.**

   If the intended assignment was direction #9, this does not resolve the scope
   mismatch. Claude explicitly kept this loop as direction #3 and points to
   `../dir9_ood` for the OOD/adversarial-plateau work.

## Misleading / False Claims Still Present

1. **"8.3x larger train budget" is misleading.**

   The GPU run increased optimizer steps from 1200 to 10000, which is 8.3x. But it
   also increased batch size from 2048 to 4096, so examples processed increased by
   about 16.7x. The writeup should say "8.3x more optimizer steps / 16.7x more
   sampled training examples."

2. **"Validated estimators" is technically true but rhetorically too strong.**

   There is now a validation artifact, so the old unsupported-claim issue is fixed.
   But the validation only covers synthetic linear Gaussian data. It should not be
   used to imply that TwoNN/MLE are accurate on real residual activations.

3. **`PLAN.md` contains stale duplicated operator-review blocks.**

   The duplicated instructions about `CODEX_REVIEW.md` and `human_feedback.md` are
   stale and refer to absent files. This is not a scientific issue, but it makes the
   project state noisy and should be cleaned up.

## What I Would Trust

I would trust the following as a pilot result:

- Layer-6 TwoNN/MLE estimates are low, around 11-13 on the pooled FineWeb sample.
- The layer-6 estimate is robust to basic centering vs z-scoring.
- Coarse position buckets do not obviously destroy the low-ID finding.
- The AE curve is not a reliable independent manifold-dimension measurement.

I would not yet trust:

- A global claim about "the GPT-2 residual stream" rather than this sample/layer.
- A claim that the residual stream is a demonstrated 12-16D curved manifold.
- A claim that the AE elbow confirms the intrinsic dimension.
