## Short Verdict

The main conclusion is now broadly faithful:

> Plateau-ness, as measured here, does not beat standard or cupbearer-style baselines on these OOD
> tasks.

The earlier serious issues were mostly fixed. `selfNLL-grad` is no longer mislabeled as a Jacobian,
`plateau-jacFrob` is a real output-distribution Jacobian proxy, Mahalanobis is fit on 1000 ID

## Findings

### High: real cupbearer results use a different ID split than plateau results

`plateau_v2.py` uses the first `N` FineWeb sequences for ID test and the next `NFIT` for covariance
fit:

```python
id_test = all_ids[:N]
id_fit = all_ids[N:N + NFIT]
```

`extract_acts.py`, used for the real cupbearer package run, instead shuffles all ID sequences first:

```python
perm = torch.randperm(id_all.shape[0], generator=g)
id_fit = id_all[perm[:N_FIT]]
id_test = id_all[perm[N_FIT:N_FIT + N_IDTEST]]
```

So `results/auroc_cupbearer.csv` is not a perfectly apples-to-apples comparison against the plateau
AUROCs in `results/auroc_table.csv`. This does **not** obviously overturn the conclusion, since the
code-shift gap is very large:

- best plateau on code: `plateau-jacFrob@input = 0.628`
- real cupbearer on code: `cup-RMD@resid6 = 0.918`, `cup-maha@resid6 = 0.913`, `cup-QUE@resid6 = 0.910`

But the writeup should not imply these are all from one identical split unless rerun that way.

Recommended fix: create and save one canonical split file, then compute both plateau and cupbearer
scores from that same split.

### Medium: `cup-QUE` is fixed relative to iter-2, but still needs cautious interpretation

The old vendored `cup_que(fit, test)` in `plateau_v2.py` recomputed covariance from the set being
scored, so ID and OOD examples were scored under different functions. That was correctly identified
as bad and the vendored `cup-QUE` rows are now marked superseded.

The real cupbearer run in `cup_eval.py` is better: it fits the detector once, then scores ID-test and
all OOD sets using the same detector. However, `cup_eval.py` passes `idtrain` as both trusted and
untrusted data:

```python
if needs_untrusted:
    kw["untrusted_data"] = tds
```

This is a consistent fixed scoring function, but it is not obviously the intended SPECTRE/QUE
anomaly-detection setup where the untrusted data is the suspicious set or mixture. Therefore:

- good: real `cup-QUE` is a legitimate cupbearer-code baseline variant;
- caution: do not overclaim it as a fully standard cupbearer benchmark protocol.

This does not hurt the main conclusion, because `cup-RMD` and naive/cup Mahalanobis already beat
plateau strongly on the code shift.

## Implementation Assessment

### Plateau metrics

`plateau-jacFrob` in `plateau_v2.py` is a reasonable Hutchinson estimator of the Frobenius norm of
`d logp / d h`:

```python
v = torch.randn(_B, logp.shape[-1], generator=g, device=DEVICE)
return (logp * v).sum()
```

Then it backprops through the selected activation and accumulates `||grad_h||^2`. This is a genuine
output-distribution Jacobian proxy, not the old self-label confidence gradient.

Caveat: it is still only a proxy for "plateau-ness"; it does not directly reproduce the original
plateau phenomenon. That is fine as long as the writeup calls it a proxy.

`selfNLL-grad` is now correctly labeled as:

```python
||d(-logp[argmax])/d h||
```

and interpreted as confidence-adjacent. This is faithful.

### Baselines

Mahalanobis is much better powered than iter-1 with 1000 fit sequences. The real cupbearer package
outputs validate the important RMD result:

- vendored `cup-RMD@resid6` on code: `0.9168`
- real package `cup-RMD@resid6` on code: `0.9178`

The real `cup-QUE` result differs substantially from the old vendored version, and the report now
correctly says the vendored `cup-QUE` rows are superseded.
