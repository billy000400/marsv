## Consistency Check

### `cup-RMD`

Mostly consistent with cupbearer's relative Mahalanobis detector.

In cupbearer, `MahalanobisDetector(relative=True)` uses:

- trusted-data mean;
- trusted-data covariance;
- pseudoinverse covariance with `rcond=1e-5`;
- diagonal correction where `diag(C) > rcond`;
- score normalized by feature dimension.

In `plateau_v2.py`, `cup_rmd()` uses:

- trusted-data mean;
- trusted-data covariance;
- pseudoinverse covariance with `rcond=1e-5`;
- diagonal correction as `1 / (diag(C) + 1e-6)`;
- no explicit division by feature dimension.

The missing dimension-normalization does not affect AUROC for a single layer, since it is a positive
constant per point. The diagonal threshold difference is a small implementation mismatch. Overall,
`cup-RMD` is a reasonable cupbearer-style reproduction, but not literally an end-to-end cupbearer
package result.

### `cup-QUE`

Less clean. The helper function is cupbearer's `quantum_entropy`, but the training/scoring protocol
in `plateau_v2.py` is not clearly equivalent to a fair cupbearer evaluation.

Main issue: `cup_que(fit, test)` recomputes the untrusted covariance from whichever set is being
scored. During AUROC assembly, ID scores are computed with an ID-test covariance, while OOD scores are
computed with that OOD set's covariance. That means ID and OOD examples are scored under different
scoring functions. This can make the AUROC hard to interpret.

The report does mention cup-QUE is transductive, but it understates this problem. Since `cup-QUE` is
not the headline winner, this does not overturn the main negative plateau result, but the method
should be caveated or excluded from headline comparisons.
